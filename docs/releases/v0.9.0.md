# numr 0.9.0

This release adds configurable decimal display precision and Kazakhstan tenge support across the native and web interfaces, and fixes how comments and aggregate queries affect totals.

## Configurable display precision

Set the maximum number of decimal places in the native configuration:

```toml
[preferences]
decimals = 4
```

With this setting, `152 / 150` displays as `1.0133`. Values from **0 through 28** are accepted. Omit the setting to keep the existing formatting, including currency-specific precision and the small-number fallback.

The preference applies to TUI results and totals, CLI expressions, files, piped input, the REPL, and JSON-RPC `display` strings. It changes presentation only: variables and subsequent calculations keep their full precision. JSON-RPC `value` fields retain their existing format for compatibility. Binary and hexadecimal output are unchanged.

Explicit precision also applies to percentages, physical units, and currencies. Very small values can display as zero at the selected precision. Decimal rounding uses midpoint-to-even rules.

The matching web and desktop release adds a persisted decimal-precision setting. Embedded integrations can configure each calculator independently; the WASM API exposes `set_decimal_places`, with `undefined` restoring the default.

## Kazakhstan tenge

KZT is now available by code, symbol (`₸`), and the `tenge` alias. It supports arithmetic, conversions, exchange-rate updates, and syntax highlighting through the shared currency catalog.

Thanks to **@Gallardo994** for [PR #20](https://github.com/nasedkinpv/numr/pull/20).

## Correct totals and previews

- References inside comments or discarded prose no longer consume the previous result or trigger implicit aggregate reads.
- Bare `total` queries stay display-only with trailing comments or parentheses, so repeating them does not inflate later totals.
- Nested `ANS`, `ans`, and `_` reads consume their source only after successful evaluation.
- Previews use the same parsed expression and current implicit values as committed evaluation, without modifying document state.
- The TUI now uses the shared full-document evaluation contract for results, variable names, and grouped totals.

## Compatibility

- Native configuration remains optional; existing configuration files continue to work without changes.
- Display precision does not change stored values or calculation precision.
- The core workspace, web app, desktop metadata, and generated WASM packages are versioned together at **0.9.0**.
- Rust **1.88** remains the minimum supported version.
